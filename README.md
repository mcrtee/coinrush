# 🪙 Coin Rush Online

Многопользовательская браузерная аркада: игроки бегают по общему полю, собирают монеты, избегают бомб и могут отнимать очки друг у друга рывком. Комнаты создаются по 4-буквенному коду; играть можно с компьютера и с телефона.

- **Сервер:** Node.js, Express, WebSocket (`ws`)
- **Клиент:** чистый HTML/CSS/JS, отрисовка на `<canvas>`, без сборщиков и фреймворков
- **Модель:** авторитетный сервер — вся логика на сервере, клиент только отправляет ввод и рисует

---

## 1. Быстрый старт

```bash
npm install
npm start
# http://localhost:3000
```

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PORT` | `3000` | Порт HTTP/WebSocket сервера |

## 2. Технические требования

### Сервер
| Параметр | Требование |
|---|---|
| Node.js | 18 или новее (`engines` в `package.json`) |
| Зависимости | `express` ^4.19, `ws` ^8.18 |
| Память / CPU | Минимальные: один общий игровой цикл на все комнаты, состояние хранится в памяти процесса |
| База данных | Не требуется |
| Порт | Один порт для HTTP и WebSocket (общий `http.Server`) |
| Хостинг | Должен поддерживать долгоживущие WebSocket-соединения (Render, Railway, Fly.io, VPS и т.п.). Serverless-платформы (Vercel, Netlify Functions) **не подходят** |
| HTTPS | Рекомендуется; клиент сам выбирает `wss://` на https-страницах |

### Клиент
- Современный браузер с поддержкой WebSocket, Canvas 2D и Web Audio (Chrome, Edge, Firefox, Safari — актуальные версии)
- Клавиатура (WASD / стрелки + Пробел) или сенсорный экран (экранный джойстик + кнопка рывка)
- Стабильное интернет-соединение; рекомендуемый пинг до сервера — до 150 мс

## 4. Архитектура

```
 Браузер A ──┐                       ┌─────────────────────────────┐
 Браузер B ──┼── WebSocket (JSON) ──▶│ server.js                   │
 Телефон C ──┘                       │  Map<код, комната>          │
                                     │  общий цикл 30 тиков/сек:   │
        ввод ───────────────────────▶│   движение → предметы →     │
        ◀──────────── состояние ─────│   столкновения → рассылка   │
                                     └─────────────────────────────┘
```

- **Авторитетный сервер.** Позиции, очки, таймеры и появление предметов считаются только на сервере. Клиент не может изменить свой счёт.
- **Тик 30 Гц.** Один `setInterval` обходит все комнаты, считает физику (`dt` ограничен 0,1 с) и рассылает полное состояние каждой комнате.
- **Клиентская интерполяция.** Клиент плавно подтягивает отрисованные позиции к присланным (`1 - 1e-6^dt`); при рассинхроне больше 120 px позиция «телепортируется».
- **Состояние в памяти.** При перезапуске сервера все комнаты теряются. Комната удаляется, когда выходит последний игрок.

### Фазы комнаты

```
lobby ──(хозяин: start)──▶ countdown (3 с) ──▶ play (30/60/90/120 с) ──▶ over (8 с) ──▶ lobby
```

В `lobby` и `countdown` игроки могут двигаться и использовать рывок, но очки не начисляются. Если игрок входит во время `play`, он сразу участвует с нулевым счётом.

## 5. Игровые правила и константы

Определены в начале `server.js`.

| Параметр | Значение |
|---|---|
| Поле / радиус игрока | 900 × 560 px / 14 px |
| Макс. игроков в комнате | 8 |
| Скорость | 230 px/с |
| Рывок | 700 px/с в течение 0,18 с, перезарядка 2,5 с |
| Длительность раунда | 30 / 60 / 90 / 120 с (выбирает хозяин) |

### Предметы

| Предмет | Эффект | Появление |
|---|---|---|
| 🟡 Монета | +1 очко; на поле всегда 8 штук | Мгновенно после сбора |
| 🌟 Золото | +5 очков | Каждые 7–12 с, живёт 8 с |
| 💣 Бомба | −3 очка (не меньше 0), оглушение 1 с; щит поглощает | Каждые 4 с, не более 4 на поле, живёт 14 с |
| ⚡ Скорость | ×1,55 к скорости на 6 с | Каждые 9 с, не более 2 бонусов на поле, живёт 12 с |
| 🧲 Магнит | Притягивает монеты в радиусе 150 px на 7 с | |
| 🛡 Щит | Один раз блокирует бомбу или кражу рывком | |

### Рывок как атака
Если во время рывка игрок касается другого, тот теряет до 2 очков (они переходят атакующему) и оглушается на 0,4 с. После удара у жертвы 1,2 с неуязвимости. Щит жертвы блокирует кражу и исчезает.

### Победа
По окончании раунда победителями считаются все игроки с максимальным счётом (если он больше 0); им увеличивается счётчик побед 🏆. Счётчик живёт, пока жива комната.

## 7. Сетевой протокол

Формат — JSON-сообщения по WebSocket; поле `t` — тип сообщения.

### Клиент → сервер

| `t` | Поля | Описание |
|---|---|---|
| `create` | `name` | Создать комнату и войти в неё |
| `join` | `name`, `room` | Войти в комнату по коду |
| `in` | `dx`, `dy` | Направление движения (−1…1; длина вектора ограничивается 1) |
| `dash` | — | Рывок |
| `start` | — | Начать игру (только хозяин, фаза `lobby`) |
| `dur` | `v` ∈ {30, 60, 90, 120} | Длительность раунда (только хозяин, `lobby`) |
| `chat` | `text` | Сообщение в чат |

### Сервер → клиент

| `t` | Поля | Описание |
|---|---|---|
| `w` | `id`, `room` | Успешный вход |
| `err` | `text` | Ошибка (комната не найдена, заполнена, сервер переполнен) |
| `s` | см. ниже | Состояние комнаты, 30 раз в секунду |
| `ev` | `k`, `id`, `x`, `y`, `v` | Игровое событие для эффектов и звука (`coin`, `gold`, `bomb`, `pu`, `shield`, `steal`) |
| `chat` | `n`, `c`, `text` или `sys`, `text` | Сообщение чата / системное сообщение |

**Состояние `s`:** `ph` — фаза, `tm` — осталось секунд раунда, `cd` — отсчёт до старта, `ov` — время до возврата в лобби, `hd` — id хозяина, `d` — длительность раунда, `ps` — игроки, `it` — предметы.

Игрок в `ps`: `i` id, `n` имя, `c` цвет, `x`/`y` позиция, `s` очки, `w` победы, `sh` щит, `sp`/`mg` секунд до конца скорости/магнита, `st` оглушён, `ds` в рывке, `dc` перезарядка рывка.
Предмет в `it`: `i` id, `k` тип (`coin`, `gold`, `bomb`, `speed`, `magnet`, `shield`), `x`/`y`, `l` оставшееся время жизни.

### HTTP
| Маршрут | Назначение |
|---|---|
| `/` | Статические файлы из `public/` |
| `/health` | Проверка работоспособности (возвращает `ok`) |

## 8. Ограничения и защита

| Мера | Значение |
|---|---|
| Максимальный размер WebSocket-сообщения | 2 КБ |
| Лимит комнат на сервере | 200 |
| Имя игрока | до 12 символов, управляющие символы и `<` `>` удаляются |
| Чат | до 80 символов, не чаще одного сообщения в 0,5 с |
| Права хозяина | `start` и `dur` принимаются только от хозяина |
| Передача хозяина | При выходе хозяина права получает следующий игрок |
| Мёртвые соединения | Ping каждые 30 с; не ответившие закрываются |
| XSS | Клиент выводит имена и чат через `textContent` |

## 9. Деплой на Render

1. Загрузите проект в репозиторий GitHub (без `node_modules`).
2. На render.com: **New → Web Service**, выберите репозиторий.
3. Настройки (подхватываются из `render.yaml`): Build `npm install`, Start `npm start`, Health check `/health`.
4. После сборки игра доступна по адресу `https://<имя>.onrender.com`.

**Особенности бесплатного плана:** сервис засыпает через ~15 минут без запросов, первое открытие после паузы занимает 30–50 секунд; все активные комнаты при этом теряются.

## 10. Известные ограничения

- Состояние только в памяти: масштабирование на несколько экземпляров сервера не поддерживается (игроки одной комнаты должны попадать на один процесс).
- Нет клиентского предсказания движения: при высоком пинге управление ощущается с небольшой задержкой.
- Нет аккаунтов и постоянного рейтинга; счётчик побед сбрасывается вместе с комнатой.
- Нет автоматического переподключения: при обрыве связи игрок возвращается в меню.
- Рассылка полного состояния 30 раз в секунду проста, но не оптимальна для комнат с большим числом игроков.

## 11. Идеи для развития

Боты для одиночной игры, препятствия и карты, командный режим, постоянный рейтинг (база данных), переподключение с восстановлением места, клиентское предсказание и дельта-сжатие состояния.
